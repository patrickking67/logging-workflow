# AGENTS.md

Guide for coding agents working in this repo. Read it before changing anything.

## What this is

A Cloudflare Workers app: a React front end and a Worker that starts a four step Workflow (`MyWorkflow`) and streams each step change to the browser over a WebSocket from a Durable Object (`WorkflowStatusDO`). It started from Cloudflare's Workflows Starter Template (MIT); keep that credit in README.md and LICENSE.

## Stack

- TypeScript, ES modules, npm with `package-lock.json` (use `npm ci`, not `npm install`, unless you are changing dependencies).
- Worker: Workflows, Durable Objects (SQLite backed, WebSocket Hibernation API), Wrangler 4. Config in `wrangler.jsonc`.
- Front end: React 19, Vite 7 with `@cloudflare/vite-plugin`, Tailwind CSS 4 through `@tailwindcss/vite` (theme in `src/index.css`, no config file).
- Tests: Vitest 3 with `@cloudflare/vitest-pool-workers`, running inside workerd.
- Node.js 20.19 or later.

## Layout

| Path | What it is |
| --- | --- |
| `worker/index.ts` | Routes and input validation: `POST /api/workflow/start`, `GET /api/workflow/status/:id`, `POST /api/workflow/event/:id`, `GET /ws` |
| `worker/workflow.ts` | `MyWorkflow`: the four steps, status reports, error reporting |
| `worker/durable-object.ts` | `WorkflowStatusDO`: stores run state, WebSocket fan-out |
| `worker/status.ts` | Pure run state rules and shared types (step names, statuses, log) |
| `src/` | React app. `App.tsx`, `components/`, `hooks/useWorkflowWebSocket.ts`, `format.ts`, `types.ts` |
| `test/` | Vitest suites for status rules, the Durable Object, the Workflow and the routes |
| `wrangler.jsonc` | Bindings `MY_WORKFLOW` and `WORKFLOW_STATUS`, assets from `dist/` as a SPA |
| `worker-configuration.d.ts` | Generated by `npm run cf-typegen`. Do not edit by hand |

## Preview for agents

`.claude/launch.json` starts `npm run dev` on port 4109. Check it with `curl -s -o /dev/null -w "%{http_code}" http://localhost:4109/` (expect 200), then select **Start a run** and confirm the log fills, the approval box appears, and Approve or Reject finishes the run.

## Conventions

- Tabs for indentation in TS, JS, JSON and CSS (see `.editorconfig`).
- Step names live in `worker/status.ts` (`STEP_NAMES`). If you rename or add a step, update `worker/workflow.ts`, `WORKFLOW_STEPS` in `src/types.ts` (including the line ranges for the code view) and the shortened source in `src/components/CodeDisplay.tsx`.
- Code outside `step.do` in the Workflow can run more than once. Keep it free of side effects other than idempotent status reports. See https://developers.cloudflare.com/workflows/build/rules-of-workflows/
- Validate anything that comes from a request in `worker/index.ts` before it reaches a binding.
- UI colors are CSS variables in `src/index.css`, used through Tailwind names (`ink`, `muted`, `run`, `wait`, `done`, `fail`, ...). Keep AA contrast in both light and dark values.
- Check current Cloudflare docs (developers.cloudflare.com) before relying on a Workers, Workflows or Wrangler API or flag.

## Safety rules

- Do not deploy, log in to Cloudflare, or change the account, routes or bindings without the owner asking.
- No secrets, tokens, account IDs or real user data in code, tests or docs. Local config goes in `.dev.vars` (gitignored).
- Do not edit `worker-configuration.d.ts` by hand or bump `compatibility_date` without reading the flags it turns on (the WebSocket close handling in the Durable Object depends on it).
- Do not remove the template credit or Cloudflare's copyright line.

## How to ship

1. Branch from `main`: `feat/`, `fix/`, `docs/` or `chore/`.
2. Small commits in Conventional Commits format, each passing `npm run check`.
3. Push and open a pull request using the template. CI runs `npm run check`.
4. The owner merges. Agents do not merge, force-push or touch `main`.

## Definition of done

- `npm run check` passes locally.
- New or changed behavior has tests.
- UI changes checked in the browser at desktop width and 375px, light and dark.
- README.md, AGENTS.md and CHANGELOG.md (Unreleased) updated when behavior or commands change.
